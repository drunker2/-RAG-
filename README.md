## 一、这是个什么系统？

### 想象一下这个场景

你是一名小学生，正在写作业时遇到了难题。你有两个选择：

1. **问 ChatGPT**：它会回答，但可能会"瞎编"答案
2. **翻课本找答案**：准确，但太慢了

**我们的系统 = 课本 + 聪明的 AI 助手**

```
┌─────────────────────────────────────────────────────┐
│                                                     │
│   你的问题 ──→ 系统先翻"课本"找相关内容             │
│                  ↓                                  │
│              找到答案后，AI 整理回答你               │
│                  ↓                                  │
│              你得到准确又有依据的答案                │
│                                                     │
└─────────────────────────────────────────────────────┘
```

这就是 **RAG（检索增强生成）系统**——让 AI 先查资料，再回答问题，这样就不会"瞎编"了！

## 二、设计思路：我们是怎么想出来的？

### 2.1 问题：AI 有时会"胡说八道"

你有没有遇到过这种情况：

```
你问：世界上最大的恐龙是什么？

AI 回答：是霸王龙！（其实是错的，应该是阿根廷龙）
```

AI 为什么会答错？因为它只是"背答案"，并不真的去查资料。

### 2.2 解决思路：像考试一样"开卷"

就像考试时，老师允许你翻书找答案，我们的系统也让 AI "开卷考试"。

```
闭卷考试（普通 AI）      开卷考试（我们的 RAG 系统）
     ↓                         ↓
  只能靠记忆                 可以翻书找答案
     ↓                         ↓
  可能记错                   答案有据可查
```

### 2.3 核心思想：检索 + 生成

我们设计的系统分成两个步骤：

```
┌─────────────────────────────────────────────────────┐
│                                                     │
│   第一步：检索（找资料）                             │
│   ─────────────────────                             │
│   就像你在图书馆，根据关键词找到相关的书籍           │
│                                                     │
└─────────────────────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────┐
│                                                     │
│   第二步：生成（写答案）                             │
│   ─────────────────────                             │
│   就像你根据找到的资料，用自己的话写出答案           │
│                                                     │
└─────────────────────────────────────────────────────┘
```

### 2.4 难点：怎么让电脑"理解"文字？

电脑只认识数字，不认识文字。怎么办？

**解决方案：把文字变成数字（向量）**

```
文字           向量（一串数字）
────           ──────────────
"苹果"    →    [0.2, 0.8, 0.1, 0.9, ...]
"香蕉"    →    [0.3, 0.7, 0.2, 0.8, ...]
"汽车"    →    [0.9, 0.1, 0.8, 0.2, ...]
```

神奇的发现：意思相近的词，数字也相近！

```
"苹果"和"香蕉"的数字很像 → 都是水果
"苹果"和"汽车"的数字不像 → 没关系
```

这就是 **向量嵌入（Embedding）**——把文字变成电脑能理解、能比较的数字。

**为什么要有重叠？**

```
假设原文是："人工智能|是计算机科学的|一个重要分支"

如果没有重叠，切成3块：
  块1: "人工智能"          ← 意思不完整
  块2: "是计算机科学的"    ← 意思不完整  
  块3: "一个重要分支"      ← 意思不完整

如果有重叠，切成3块：
  块1: "人工智能|是计算机科学的"
  块2: "是计算机科学的|一个重要分支"
```

**向量相似度是什么意思？**

```
想象每个向量是一个箭头，从原点指向某个方向：

        ↑ [0.1, 0.9] "苹果"
       /
      /
     /  ← 角度小 = 很相似
    / 
   •──────────→ [0.9, 0.1] "汽车"
    \
     \
      \ ← 角度大 = 不相似
       \
        ↓ [0.2, 0.8] "香蕉"

"苹果"和"香蕉"的箭头方向相近 → 相似度高
"苹果"和"汽车"的箭头方向相反 → 相似度低
```

```python
# hybrid_retriever.py 的核心逻辑

class HybridRetriever:
    """
    混合检索——用两种方法一起找资料
    
    方法1（向量检索）：理解意思，找相关内容
          问题："水果的营养价值" → 找到"苹果含有丰富维生素"
    
    方法2（关键词检索）：精确匹配关键词
          问题："Python教程" → 找到包含"Python"字样的文档
    
    混合使用：两种结果合并，效果最好！
    """
    
    def retrieve(self, query, k=4):
        # 方法1：向量检索（理解意思）
        vector_results = self.vector_search(query, k=20)
        
        # 方法2：BM25关键词检索（精确匹配）
        keyword_results = self.bm25_search(query, k=20)
        
        # 合并结果，重新排序
        merged = self.merge_and_rerank(vector_results, keyword_results)
        
        # 返回最相关的k个
        return merged[:k]
```

#### 代码4：问答引擎——生成最终答案

```python
# rag_qa.py 的核心逻辑

class RAGQA:
    """
    问答引擎——就像一个聪明的学生
    
    它会：
    1. 先"翻书"找到相关内容
    2. 根据"书本内容"写出答案
    3. 标注答案来自哪里（可追溯）
    """
    
    def ask(self, question):
        # 第1步：检索相关文档
        docs = self.retriever.get_relevant_documents(question)
        
        # 第2步：构建提示词
        prompt = f"""
        请根据以下参考资料回答问题。
        如果资料中没有答案，请说"我不知道"。
        
        参考资料：
        {docs}
        
        问题：{question}
        
        答案：
        """
        
        # 第3步：调用AI生成答案
        answer = self.llm.generate(prompt)
        
        # 第4步：返回答案和来源
        return {
            "answer": answer,
            "sources": docs,  # 告诉用户答案来自哪些文档
            "confidence": self.calculate_confidence(answer, docs)
        }
```

## 五、如何使用？

### 5.1 安装依赖

```bash
# 安装所有需要的库
pip install -r requirements.txt
```

### 5.2 配置 API Key

创建 `.env` 文件：

```bash
# 选择LLM提供商（推荐用阿里云通义千问）
LLM_PROVIDER=dashscope
DASHSCOPE_API_KEY=你的API密钥

# 选择存储后端
VECTOR_STORE_BACKEND=postgres

# PostgreSQL 配置
PG_HOST=localhost
PG_PORT=5432
PG_USER=postgres
PG_PASSWORD=123456
```

### 5.3 运行系统

```bash
# 方式1：网页界面
streamlit run app.py

# 方式2：命令行交互
python main.py --mode interactive

# 方式3：API服务
python api.py
```

### 5.4 常用命令

```bash
# 导入文档
python main.py --mode index --source ./documents/

# 单次提问
python main.py --mode query --question "什么是AI？"

# 交互模式（多轮对话）
python main.py --mode interactive

# 使用高级功能
python main.py --mode interactive \
    --provider dashscope \
    --model qwen-plus \
    --optimize-query \    # 优化问题
    --hybrid              # 混合检索
```

## 总结

### 一句话概括

```
RAG系统 = 会查资料的AI

它先在你的知识库里找到相关内容，再让AI根据这些内容回答问题，
这样AI就不会"瞎编"，答案有据可查！
```

### 核心技术点

| 技术 | 解决什么问题 | 类比 |
|------|-------------|------|
| 向量嵌入 | 让电脑理解文字意思 | 给每个词贴数字标签 |
| 向量检索 | 找到意思相近的内容 | 找标签相近的书 |
| 混合检索 | 提高搜索准确率 | 两种方法一起找 |
| LLM生成 | 整理出流畅答案 | 聪明的学生写作文 |

### 适合谁用？

- **学生**：做作业时查资料、问问题
- **企业**：搭建知识库，帮助员工快速找到答案
- **开发者**：学习 RAG 技术，构建智能应用
